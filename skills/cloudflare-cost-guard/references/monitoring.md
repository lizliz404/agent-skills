# 监控与频率迁移合同

## 权限按能力核验

凭据状态、账号/资源清单、analytics、billing、native alerts 分别记录。
只有确认凭据失效、撤销或整体认证失败才停止整把凭据的请求。单个 API 403
只停止该能力的重复请求，继续已授权且已验证可读的独立能力；错误按实际响应分类。
验证接口自身不可读、网络失败、限流或 schema 错误不自动证明 token 无效。
用户 token 与账号 token 的核验路径可能不同，先识别类型，不为补缺口扩权。
依据：[Cloudflare token 权限与资源范围](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/)。

## 频率、覆盖窗口、评估窗口

迁移频率一起核对：timer、查询区间、成功水位、阈值、失败时限、watchdog、
通知节奏、超时、防重入与补跑。仅改 timer 不能证明没有漏报或误报。

- 使用半开区间 `[start,end)`，end 按已测的数据成熟延迟确定；固定两分钟不是厂商保证。
  每数据集保存成功覆盖水位，正常 start 从水位接续，首次至少回看一个运行周期。
  失败或截断不推进未覆盖段的水位；历史补读按 API 跨度分段。无法补回的区间明确报告。
- 迟到数据可以重叠重查；使用替换、非重叠分桶或去重，不重复累加重叠窗口。
  数据集行数触顶时分页/分割；不能取前 N 项就标完整，多账号独立记成功。
- **采集覆盖区间与风险评估窗口分开。** 四小时补跑量不能直接和一小时阈值比较；
  按阈值对应的时间桶评估。四小时平均值也不能证明没有某小时尖峰。
  仅有汇总而没有时间分布时，标记该评估证据不足，另用经过校准的累计风险规则。
- 最近窗口、滚动24h、账期累计分别校准。15m 阈值不直接搬到60m，也不盲乘四。
  阈值注明 metric、unit、window、resource/account、operator、value、基线时间与风险依据。
  CPU、DO时长、R2类别的真实单位需核验；用量阈值不冒充美元预算。

## 数据健康与有效空结果

尝试完成时间、完整成功时间、真实 data_at 分开。失效判断分别捕捉“不再运行”和“数据持续不可读”。
权限失败、截断、过旧、有效空结果分别记录，不能从进程结束推断完整健康。
验证授权、分页、过滤、数据成熟度和接口空结果语义后，空结果可记成功空/无观测事件；
不能由此推断零账单。当前无资源可标当前不适用，不能倒推历史无消费。
有资源而空结果含义/延迟未确认时保持未知，不能宣称完整健康。

stale_after 与调度周期、抖动、最长合法运行和数据延迟匹配；1h调度不硬抄20m。
按可容忍的数据盲区时长设置 max_blind_age，独立于失败轮数。确定性权限/凭据错误
及时记录与路由，瞬态错误采用有限重试；三轮小时级失败不能冒充15分钟失效检测。
已有调度器、防重入锁、API超时、私密原子状态即可。状态至少保存各数据集水位、
pending、失败原因、成功时间与真实数据时间。只禁通知不一定禁止写状态；核查实际命令契约。

同机 watchdog 无法证明整机离线时仍能告警；复用已有外部探活，缺失就报告，不默认建接管系统。

## R2、账单与摘要

6h 存储快照是存量，不加总当累计；增长比较同桶、同jurisdiction、同单位且有时间戳的样本。
缺历史就无法算。短期快照可能漏峰值，当前GB不能冒充GB-month发票。
采样用量、免费额度、价格估算、实际账单分别标注；公开GET是否形成计费操作需按缓存、
存储类别和实际用量核验，不为监控列全桶/下载对象。
七张每日滚动24h快照可能重叠；只有已证明的非重叠覆盖才可声称精确周总量。

依据：[R2 analytics](https://developers.cloudflare.com/r2/platform/metrics-analytics/)、
[R2 pricing](https://developers.cloudflare.com/r2/pricing/)。
