# Domain fork: e-commerce storefront

> Evidence tier: Templated (synthesized, not build-tested)

SaaS product-theater rules partially apply. Storefronts trade window chrome for **merchandise density**, trust, and conversion path.

## What changes

| SaaS default | Storefront fork |
|--------------|-----------------|
| WindowChrome mocks | Product photography / packshots (licensed or original) |
| Pipeline charts | Price, variant, review density |
| Dark feature band | Often lifestyle full-bleed + sticky ATC |
| Editorial serif pull | Brand display face + body; serif optional |
| Composite refs | 3–5 category leaders still required when shipping |

## Capture extras

- PDP + collection + homepage (not homepage alone)
- Mobile screenshots mandatory (conversion is mobile-skewed)
- Extract promo bar / announcement height — CLS risk

## Density gates

- IMR bands still apply, but "ink" may be photography — measure carefully (photo ≠ empty)
- Prefer ED on filter/nav chrome; don't treat every `<img>` leaf as theater density
- Failure Gallery A still applies to empty white feature grids

## Legal

Never scrape and ship competitor product photos. Replicate layout language; shoot or license your own merchandise imagery.

## Anti-patterns

- Forcing traffic-light WindowChrome onto a fashion brand
- Purple AI glow on a CPG site
- Desktop-only density pass
