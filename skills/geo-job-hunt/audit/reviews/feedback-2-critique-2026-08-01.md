## 原问:Liz 问这是"为了喷而喷"还是有参考价值

原文五条:

1. **核心功能缺少实测证据支撑**:整个系统中,最关键的动作"投递(user-apply-job)"的成功响应形态从未被实测过,脚本和文档均标记为 OK_UNVERIFIED。这是目前最大的不确定性来源。

2. **限流策略的参数依据**:脚本采用了 1.3s 基础间隔、90-120s 退避、6h 探测间隔等参数,虽然描述称"基于实测",但审计报告中未包含用于得出这些具体数值的测试数据或日志分析,长期有效性有待验证。

3. **API Schema 演进的风险**:jobKind 枚举值未证实、salaryFloor/Cap 为 string 类型等细节,表明对猎聘 API 的理解仍有模糊地带。如果官方更新 schema,可能需要对脚本进行相应调整。

4. **对 Hermes 平台的耦合**:生态拓扑严重依赖 Hermes 的 symlink 和 cron 机制(且 cron 还要求实体副本),在另一台机器上完整复现可能需要更多手动步骤。

5. **部分历史负担未清理**:DEFAULT_EXTRA_KEYWORDS 中的公司名硬编码、v3 历史草稿的引用等,属于不影响功能但可能影响长期维护的细节。
